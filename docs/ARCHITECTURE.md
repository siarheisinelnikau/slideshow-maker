# Architecture

Preview work does not block the surrounding editor. The capacity-one worker can retain one explicit user action behind its in-flight preview, then dispatch that action before requesting another frame. Playback generations invalidate late frames/errors after edits, seeks and play/pause changes; normal clock advancement can still display a useful completed frame. Each completed frame gets a fresh egui texture handle because the pinned software renderer caches image meshes by texture ID, not updated pixel content. Replacing the handle frees the preceding frame and refreshes only the video primitive while keeping control styling stable.

`build.rs` embeds the original `assets/SlideshowMaker.ico` as Windows icon group 1, together with product/version metadata. Its eleven 32-bit sizes cover 16–256 physical pixels. `app_icon.rs` loads DPI-appropriate small and large images from that same native resource for the title bar and taskbar, and reloads them on a DPI change. The bounded native diagnostic reads only its own `WM_GETICON` handles and checks both bitmap sizes; temporary GDI bitmaps from this inspection are released. No icon-cache reset or Windows setting change is required by the implementation. `scripts/generate-icon.py` reproduces the SVG, PNG and ICO from shared original vector geometry.

`model.rs` contains versioned project data, validation, frame counts, proportional duration changes, and the timeline. Slide durations sum to the exact project duration. Transitions occupy the tail of the outgoing slide, limited to half its duration. Export rounds the final duration up to a complete frame.

`render.rs` implements the shared preview/export CPU compositor. It reads supported image files with explicit decoder limits, applies metadata orientation, caches at most two decoded/scaled photos, applies user rotation, fits or deliberately crops, draws original template colors and captions with the embedded Ubuntu font, and blends transitions. Preview uses height 360 while export uses the chosen output height. Font advances produce bounded character wrapping; complex-script shaping, emoji coverage and word-aware line breaking are future work. Preview is silent and plays at a target of about 12 updates per second. It is not an audio/video playback engine.

`audio.rs` decodes MP3, WAV, FLAC, Ogg Vorbis, M4A (AAC-LC/ALAC), ADTS AAC-LC and AIFF through pinned, in-process Symphonia codecs, without OS codecs, audio output or subprocesses. Import validation runs on the existing media worker; export decodes with cancellation checks between packets. Input is limited to 128 MiB and accumulated PCM16 samples to 256 MiB; conversion buffers are reused and vector growth is bounded. Mono/stereo at 8–96 kHz is accepted, including higher-bit-depth/floating-point PCM. Gapless trimming is enabled when the format/codec supports it. Decode errors and failed verification reject damaged inputs; declared container durations are checked in packet time units, excluding MP3 bitrate estimates. Empty Vorbis priming packets are skipped.

`avi.rs` writes RIFF AVI with MJPEG video, PCM16 audio, chunk padding, stream headers and a seek index. Music retains its sample rate, is trimmed or repeated to the exact video-frame duration, and receives volume adjustment and edge fades. The writer rejects output near 2 GB; OpenDML is not implemented.

`export.rs` renders one frame at a time, compresses it as JPEG and interleaves the corresponding audio samples. Cancellation is checked before and during soundtrack decoding, between frames, while waiting for FFmpeg, and during final copying. Optional FFmpeg conversion uses separate arguments (no shell command construction), hidden process creation, bounded encoder threads, a drained progress pipe and an error log. MP4 uses the native `mpeg4` and `aac` encoders. Every job owns a temporary directory. Successful results are copied to a same-directory temporary file, synced and published with `persist_noclobber`; the requested destination is absent on failure. Source media and existing outputs are never changed.

`ui.rs` provides the egui editor. One persistent worker owns photo decoding, dialogs, project I/O, settings writes, and exports. Requests and results use capacity-one channels; export runs on an immutable project snapshot. Only explicit foreground operations block editing. Preview results carry a revision and generation so obsolete frames and errors are discarded. Expensive decoding may make the preview lag but does not block the UI thread. The single worker also means project saving waits for an export to finish or be cancelled. A separate single network job handles update checking/downloading. No worker runs a retry loop.

`desktop.rs` owns a reactive winit host, `egui_software_backend` CPU rasterization and softbuffer's Windows GDI presentation. No OpenGL, glutin, eframe, wgpu or Direct3D renderer is used. `about_to_wait` explicitly selects `Wait` or the earliest `WaitUntil` deadline; later repaint requests cannot postpone earlier work. OS exposure can present the retained bitmap without rebuilding UI. Minimized/occluded windows skip rasterization; pending texture uploads are retained until a visible frame consumes them. Close requests pass through the editor's unsaved-work/cancellation guards before exit. DPI, clipboard, IME and viewport commands are delegated to egui-winit. Textures and native resources are kept on the window thread and repaint callbacks are detached at shutdown.

`rasterizer.rs` provides the shared production/capture CPU renderer. The upstream paired-triangle-to-rectangle fast path is disabled because a real fractional-scale photo capture reproduced an out-of-bounds texture read there. Caching and the other raster optimizations remain enabled; the safe triangle path is covered by a regression that checks a scaled photo's center and final edge pixel. The native host also compares shapes, textures, size and scale with the last scene: useful pointer hit-testing still runs, but an unchanged scene skips tessellation, rasterization and presentation. An explicit native exposure/restore can still blit the retained bitmap; this is separate from content invalidation and has a regression for pointer motion over the empty editor.

`capture.rs` handles `--screenshot ABSOLUTE_PNG --screen editor|settings|export [--project PATH] [--size WIDTHxHEIGHT] [--scale 1..2]` before normal startup. It constructs the real editor with isolated settings and no startup requests, prepares its real compositor preview, runs the production UI and rasterizer offscreen until settled (at most eight frames/eight seconds), atomically saves a client-area PNG and metadata, and exits. Logical dimensions and native scale are supplied separately to avoid double-applying DPI scaling. `scripts/capture-review.py` supervises each child with a 15-second external timeout and validates the decoded PNG dimensions. No window, GDI presentation or desktop input is needed for static captures; they do not certify native presentation or interactions.

`--diagnostic-report ABSOLUTE_JSON` instead runs the native CPU/GDI host with an isolated empty project and no network/settings writes. After startup settles, it takes five-second visible-idle and hidden samples, restores the window, settles again, takes a five-second restored-idle sample, writes counters/CPU/event causes and exits. `scripts/verify-runtime.py` enforces a 26-second external timeout on only its own disposable child. The old marker-file startup sampler was removed because a sample containing startup and pointer events cannot establish idle behavior. A panic during normal operation attempts to save `SlideshowMaker-crash.txt` beside the executable; read-only installations may prevent that diagnostic.

`storage.rs` validates project files (maximum 4 MiB), resolves relative media paths against the project directory, saves atomically, and stores settings separately from portable executables. Save operations compare canonical paths to reject overwriting a referenced source. Imports use absolute file paths from native dialogs; projects are references rather than media bundles.

`updater.rs` uses the public GitHub HTTPS release API without credentials. It compares semantic versions, excludes drafts/prereleases, selects the canonical portable x64 executable and checksum, enforces size/origin constraints, verifies SHA-256 and PE architecture, and stages next to the running app. Downloading/installing requires explicit UI actions. `install-update.ps1` runs hidden only after the user chooses restart, waits for exit rather than killing the editor, backs up the old executable, replaces/relaunches it, and restores it if those operations fail. This is file-operation rollback, not application-health monitoring or code-signature verification. The helper never modifies project files or settings. Clean-machine installation, locked files, denied permissions, process timing and rollback need manual tests.

The initial session allowed only headless checks. A later user instruction authorized GUI checks and real screenshots. Tests use synthetic media; update replacement, audio playback, system settings and driver changes remain outside this verification. Synthetic render/export programs are separate Cargo examples with no GUI or network.
