# Architecture

`model.rs` contains versioned project data, validation, frame counts, proportional duration changes, and the timeline. Slide durations sum to the exact project duration. Transitions occupy the tail of the outgoing slide, limited to half its duration. Export rounds the final duration up to a complete frame.

`render.rs` implements the shared preview/export CPU compositor. It reads supported image files with explicit decoder limits, applies metadata orientation, caches at most two decoded/scaled photos, applies user rotation, fits or deliberately crops, draws original template colors and captions with the embedded Ubuntu font, and blends transitions. Preview uses height 360 while export uses the chosen output height. Font advances produce bounded character wrapping; complex-script shaping, emoji coverage and word-aware line breaking are future work. Preview is silent and plays at a target of about 12 updates per second. It is not an audio/video playback engine.

`avi.rs` writes RIFF AVI with MJPEG video, PCM16 audio, chunk padding, stream headers and a seek index. WAV parsing accepts PCM16 mono/stereo only. Music retains its sample rate, is trimmed or repeated to the exact video-frame duration, and receives volume adjustment and edge fades. The writer rejects output near 2 GB; OpenDML is not implemented.

`export.rs` renders one frame at a time, compresses it as JPEG and interleaves the corresponding audio samples. Cancellation is checked between frames, while waiting for FFmpeg, and during final copying. Optional FFmpeg conversion uses separate arguments (no shell command construction), hidden process creation, bounded encoder threads, a drained progress pipe and an error log. MP4 uses the native `mpeg4` and `aac` encoders. Every job owns a temporary directory. Successful results are copied to a same-directory temporary file, synced and published with `persist_noclobber`; the requested destination is absent on failure. Source media and existing outputs are never changed.

`ui.rs` provides the native eframe editor. One persistent worker owns photo decoding, dialogs, project I/O, settings writes, and exports. Requests and results use capacity-one channels; export runs on an immutable project snapshot. Controls are disabled while that worker is occupied. Preview results carry a revision so stale images are discarded. Expensive decoding may make the preview lag but does not block the UI thread. The single worker also means project saving waits for an export to finish or be cancelled. A separate single network job handles update checking/downloading. No worker runs a retry loop. Idle rendering relies on eframe/winit wake events; timed repaint requests occur only for playback, export/download progress. Actual idle/visible behavior still requires a packaged Windows measurement.

`storage.rs` validates project files (maximum 4 MiB), resolves relative media paths against the project directory, saves atomically, and stores settings separately from portable executables. Save operations compare canonical paths to reject overwriting a referenced source. Imports use absolute file paths from native dialogs; projects are references rather than media bundles.

`updater.rs` uses the public GitHub HTTPS release API without credentials. It compares semantic versions, excludes drafts/prereleases, selects the canonical portable x64 executable and checksum, enforces size/origin constraints, verifies SHA-256 and PE architecture, and stages next to the running app. Downloading/installing requires explicit UI actions. `install-update.ps1` runs hidden only after the user chooses restart, waits for exit rather than killing the editor, backs up the old executable, replaces/relaunches it, and restores it if those operations fail. This is file-operation rollback, not application-health monitoring or code-signature verification. The helper never modifies project files or settings. Clean-machine installation, locked files, denied permissions, process timing and rollback need manual tests.

The session's code-only restriction means no GUI/app launch, real-media access, audio playback, update replacement, or driver changes occurred. Synthetic render/export programs are separate Cargo examples with no GUI or network.
